# agent-compare-next

Next.js (App Router, TypeScript) port of `../agent-compare/index.html` — a side-by-side
chat UI for comparing `agent-cortex` and `agent-claude` on the same question.

Same behavior as the original static page: fires both agents in parallel over SSE, shows
each one's step trail and answer as it streams, and reports per-turn cost/tokens/TTFT/latency.
Also adds a light/dark theme toggle (persisted, no flash on reload).

## Prerequisites

Both agents must already be running — this UI only talks to them, it doesn't start them:

```bash
# from the repo root, in two separate terminals
cd agent-cortex/apps/agent && .venv/bin/python -m uvicorn app.main:app --port 8000
cd agent-claude/apps/agent && .venv/bin/python -m uvicorn app.main:app --port 8001
```

See `../agent-claude/RUNBOOK.md` if either agent isn't set up yet — it covers the venv,
`.env`, and the observability install traps.

## Run

```bash
cp .env.example .env.local   # only needed if the agents run somewhere other than localhost
npm install
npm run dev   # http://localhost:3000
```

Agent URLs come from `NEXT_PUBLIC_AGENT_CORTEX_URL` / `NEXT_PUBLIC_AGENT_CLAUDE_URL` in
`.env.local` (see `app/page.tsx`), defaulting to `http://127.0.0.1:8000` / `:8001` if unset.
The `NEXT_PUBLIC_` prefix is required — these are read client-side (`fetch` runs in the
browser), so Next.js needs to inline them into the client bundle at build time. Changing
`.env.local` requires restarting `next dev` — env vars are only read at server startup.

## Layout

| Path | |
|---|---|
| `app/page.tsx` | the whole UI — two-panel layout, SSE streaming, step trail, metrics chips, theme toggle |
| `app/globals.css` | styling, incl. `[data-theme='dark']` / `[data-theme='light']` token sets |
| `app/layout.tsx` | fonts + the inline theme-init script (runs before paint, avoids a flash of the wrong theme) |

The streaming/metrics logic in `page.tsx` is deliberately imperative (refs + direct DOM
writes) rather than idiomatic React state — it mirrors the original vanilla-JS script closely
so the already-verified SSE parsing and cost math didn't need to be re-derived.

## Notes

- Pinned to `next@16.3.4` — earlier 14.x releases pulled in have a known critical
  DoS vulnerability; this version has 0 flagged by `npm audit`.
- `AGENTS.md` in this directory is auto-generated by `next dev` (warns that this Next.js
  version differs from older training data) — safe to leave in place, it gets re-added anyway.
